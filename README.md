# SmartWriting

A multi-project writing & worldbuilding **PWA**. This repo currently contains the
**Phase 1 skeleton**: an installable, offline-capable app where you create and
switch between projects, organize Books → Chapters, write in a distraction-light
Markdown editor, and capture per-chapter metadata — all persisted **locally**
(IndexedDB). No backend is connected yet.

See `Ilema-App-SPEC.md` for the full multi-phase brief.

## Run locally

Requires Node 18+ (developed on Node 22).

```bash
npm install      # install dependencies
npm run dev      # start the dev server (Vite) — open the printed http://localhost:5173
```

Production build / preview (this is what exercises the real service worker):

```bash
npm run build    # outputs dist/ with the PWA manifest + service worker
npm run preview  # serves the built app, e.g. http://localhost:4173
```

### Install as an app
Open the dev/preview URL in Chrome/Edge (desktop or Android) or Safari (iOS) and
use **Install app / Add to Home Screen**. The app shell is precached, so it opens
offline; all your writing lives in the browser's IndexedDB on that device.

## What each part does

| Area | File(s) | Role |
|------|---------|------|
| **PWA config** | `vite.config.js`, `public/manifest`\* , `public/favicon.svg`, `scripts/gen-icons.mjs` | Vite + `vite-plugin-pwa` generate the web manifest and a Workbox service worker that precaches the shell for offline use. Icons are generated by a tiny dependency-free script into `public/icons/`. |
| **Data shapes** | `src/data/types.js` | Record factories mirroring SPEC §3 (`projects`, `chapters`, `characters`, `places`, `character_locations`). Every non-project record carries `project_id`. |
| **Data-access interface** | `src/data/repository.js` | The single contract the whole UI talks to. **The one swap point** — replacing the local backing with Supabase later means changing one line here, not the UI. |
| **Local implementation** | `src/data/localRepository.js`, `src/data/db.js` | The repository contract implemented over IndexedDB (`idb`), one object store per table, indexed by `project_id`. Handles cascading deletes. |
| **App store** | `src/state/store.jsx` | React context that loads data for the active project, exposes all CRUD actions, and persists the active project + chapter across reloads. Components never touch the repository directly. |
| **Project shell** | `src/components/ProjectSwitcher.jsx` | Create / rename / delete projects and switch the active one. Selecting a project scopes the entire UI to it. |
| **Books → Chapters tree** | `src/components/Sidebar.jsx` | Per-project sidebar tree. Create / rename / delete books and chapters; click a chapter to open it instantly. |
| **Editor** | `src/components/Editor.jsx`, `src/components/ChapterView.jsx` | Distraction-light Markdown textarea with a toggleable live preview. Edits save debounced (500 ms) so typing never blocks; a "speichert…/gespeichert" indicator shows save state. |
| **Metadata panel** | `src/components/MetadataPanel.jsx` | Per-chapter: status (entwurf/aktiv/überarbeitung/final), POV, one-line summary, characters present, places present, and — for each present character — **where they are this chapter**. The location pickers write `character_locations` rows now, so the Phase 3 map timeline can read them later. |

\* The manifest is generated into `dist/` at build time by `vite-plugin-pwa`.

## Data model notes

`character_locations` is the timeline backbone. A row means:

- `character_id` set, `place_id` null → character present, location not yet set
- `character_id` set, `place_id` set → character present at a place
- `character_id` null, `place_id` set → place present in the chapter (no character bound)

This keeps "characters present", "places present", and per-character location all
in the one SPEC table, ready for the map timeline later.

## Security

Nothing here references Supabase yet — there is **no** Supabase client, no env
vars, and **no service-role key** anywhere in the codebase (verified). When
Supabase is added in a later phase, the client must use only the **anon key**
plus per-user auth + RLS; the service-role key must never reach the browser.

## Not yet built (later phases, per SPEC)

3D map, Google Drive backup, the translator, chapter versioning, the
